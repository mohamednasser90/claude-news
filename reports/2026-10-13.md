## 3. Learn: to get better at Claude skills

Ordered by return on time:

1. **Anthropic's engineering write-up on skills.** [Lessons from building Claude Code: How we use skills](https://claude.com/blog/lessons-from-building-claude-code-how-we-use-skills). Primary source; read first.
2. **Study the official reference plugins.** Start with `claude-plugins-official` and `knowledge-work-plugins`, then `tres-finance-plugin` in the community repo for eval-backed skills.
3. **Description engineering.** The skill `description` decides whether it triggers. Claude reads all skill descriptions at startup and loads a skill's body only when it matches. Write descriptions that say *when* to use the skill, with concrete trigger phrases.
4. **Progressive disclosure.** Keep `SKILL.md` short. Move detail into `references/`, `scripts/`, and `examples/`, as `html-plan` and `quickdesign` do.
5. **Evals.** Add `evals/evals.json` to each skill and measure triggering and output quality. The `skill-creator` skill covers this workflow.
6. **Frontmatter and tool scope.** Check `allowed-tools` and similar fields against the official docs before relying on them. Secondary guides disagree on details.
7. **Packaging.** Build in `.claude/skills/` first, then bundle into a plugin with `.claude-plugin/plugin.json` once it's stable.
8. **Security.** Read any third-party `SKILL.md` before granting it write access or shell execution. The community repo is not audited.
